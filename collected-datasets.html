Section 5

Scheme Reference & Eligibility Tables

Important reconciliation needed: these tables reference PMEGP, MUDRA, PM-SVANidhi, Stand-Up India, and DAY-NRLM/SVEP — general national schemes with different eligibility logic than the NSFDC-specific margin-money structure (10% in → 90% loan, 6.5%/8% tiers) that SIH26091's own PS text describes. Before building the eligibility gate, decide explicitly: is the product scoped to NSFDC/NBCFDC-style corporations only (per the PS's worked example), or broadened to this wider scheme set? Building against both without deciding will create two different eligibility rule shapes in the same codebase — pick one and log the decision.

Feeding This to Antigravity

This data maps directly onto schema.md's village_metrics table (from the Antigravity context pack). The mapping below is what to tell Antigravity to build — a transformation script, not a redesign of the schema.

field-mapping.md
village_metrics.village_id          <- village_amenities.Village Code
village_metrics.village_name        <- village_amenities."Village Name"
village_metrics.block               <- village_amenities."Sub District Name"
village_metrics.district            <- village_amenities."District Name"
village_metrics.population          <- village_amenities."Total Population of Village"   [Verified]
village_metrics.households          <- village_amenities."Total   Households"             [Verified]
village_metrics.establishments_*    <- NOT available at village level.
                                        Derive proportionally from shrug_economic."Total Firms"
                                        (block-level) split by population share as a first-pass
                                        [Derived], OR mark [Insufficient Data] per category until
                                        a real village-level establishment count is sourced.
village_metrics.avg_monthly_consumption <- NOT in this workbook. Still [Insufficient Data]
                                        unless sourced separately (SECC-based estimate).
village_metrics.data_source_population   = "Census 2011 PCA / Village Directory (collected)"
village_metrics.data_source_establishments = "SHRUG-style block-level (collected), category-level pending"
village_metrics.last_verified_date  = date you extracted this workbook

What to tell Antigravity, concretely

next-prompt-to-antigravity.txt
Real data has replaced the mock data. Build a one-time transformation script
(Python, pandas) that reads the two source workbooks
(sih_data_collection.xlsx sheets: village_amenities, census_metrics,
shrug_economic; MGNREGA_Muzaffarpur_Gaya_Panchayat_Data.xlsx sheets:
aurai_data, sherghati) and outputs data/village_metrics.json,
data/scheme_terms.json, and data/eligibility_rules.json matching schema.md
exactly, using the field mapping in collected-datasets.html Section 8.

Establishment counts by category (Dairy/Retail/Textiles) are NOT in this
data at village level -- do not invent them. Either (a) derive a
population-weighted split from the block-level "Total Firms" figure and
tag it [Derived], or (b) leave the field null and let the app render
"Insufficient Data" for that specific line, per rules.md R2. Do not default
to (a) silently -- confirm which approach the team wants before hardcoding it.

Before finalizing eligibility_rules.json: confirm with the team whether the
product targets NSFDC-style corporation schemes (per the original PS text)
or the broader PMEGP/MUDRA/Stand-Up India/SVEP set in the Scheme Rules
sheet -- these have different eligibility shapes and should not both be
half-implemented.
